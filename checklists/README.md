# Checklists

## Purpose

A fast, condensed action checklist per `playbooks/` entry — for someone
who already knows the playbook and needs a quick pass/fail pass in the
moment, not the full reasoning again. Distinct from `verification/`'s
checklists, which check the quality of a work product (code, a deploy,
a doc); these check whether the right *response actions* happened during
a live situation.

## Format

One file per playbook, same base filename. Each is a short checklist
extracted from its playbook — no new content, no restated reasoning,
just the action items in checkable form. If a checklist item needs
justification, that justification lives in the playbook, linked from
here.
