# Checklist: Large Refactor Decision

Full reasoning: `playbooks/large-refactor-decision.md`

- [ ] Reason tied to a real, current cost (not just "it's not clean")
- [ ] Incremental approach considered and ruled out if a big-bang
      approach was chosen instead
- [ ] Test coverage for current behavior confirmed before refactoring
      starts
- [ ] Module owner(s) involved before work starts, not at review
- [ ] Overlapping in-flight work identified and sequenced
- [ ] If stalled/abandoned, the decision and reason are recorded
