# Glossary

## Purpose

Terms specific to this project or team that a newcomer wouldn't already
know from general software vocabulary — internal shorthand, domain
terms, or acronyms used in conversation and code without explanation.

## When to add an entry

The first time someone has to ask "what does X mean" in a review, a
planning doc, or onboarding — that's the signal the term belongs here,
not a reason to assume it's obvious next time.

## Format

A single running file, `glossary.md`, alphabetically ordered. Not one
file per term — a glossary is meant to be skimmed as a whole.
