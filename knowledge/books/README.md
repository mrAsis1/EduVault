# Books

## Purpose

Notes on books that materially shaped how this team builds software —
not book reports, not full chapter summaries. Each entry should answer
"what did we actually change because of this book," not just "what is
this book about."

## When to add an entry

After finishing a book (or the relevant chapters) that changed a real
decision, convention, or default in this codebase or team practice. If
nothing changed as a result, it's a reference, not a lesson — consider
`references/` instead.

## Format

One file per book: `[author-title-in-kebab-case].md`, using
`book-notes-template.md`.
